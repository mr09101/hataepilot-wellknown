# 하태파일럿 무선 업데이트 운영 안내

## 구성과 공개 경계

- Cloudflare Worker `hataepilot-updates`는 `hataepilot.com/updates/*`만 처리합니다.
- `/app-recovery/` 안내 화면은 Pages 정적 자산입니다. Worker 무료 요청량이 소진되어도 설치 안내 자체는 열 수 있습니다.
- R2 버킷 이름은 `hataepilot-updates`, 저장 클래스는 Standard, 공개 도메인은 없는 private 상태여야 합니다.
- R2에는 `current.apk`, `recovery.apk`, `manifest.json` 세 키만 둡니다. 게시 도구는 다른 키를 발견하면 중단하며 삭제하지 않습니다.
- `UPDATE_TOKEN_SHA256`만 Worker secret으로 넣습니다. 원문 비밀번호는 정확히 32 random bytes를 패딩 없이 base64url로 쓴 43자 문자열이며, 코드·manifest·R2 metadata에 넣지 않습니다.

## 로컬 검증

기본 명령은 원격 읽기나 쓰기를 하지 않습니다.

```powershell
npm run ota:test
node --check updates/src/worker.js
node --check updates/src/budget.js
node --check updates/publish.mjs
```

게시 dry-run은 APK 파일을 직접 해시하고 Android SDK의 `aapt dump badging`과 `apksigner verify --verbose --print-certs` 결과를 검사합니다. package, versionCode, versionName, minSdk, 인증서 SHA-256, 파일 SHA-256과 크기가 manifest와 모두 같아야 합니다. `application-debuggable` APK는 거절합니다.

```powershell
node updates/publish.mjs `
  --current <current.apk> `
  --recovery <recovery.apk> `
  --manifest <manifest.json> `
  --previous-version-code <현재-설치판-versionCode> `
  --trusted-certificate-sha256 <기존-신뢰-인증서-SHA256>
```

`--publish`가 없으면 결과의 `mode`는 `dry-run`, `remoteWritesPerformed`는 `false`입니다.

## 원격 게시 준비와 실행 경계

원격 게시에는 AWS CLI v2와 다음 환경 변수가 필요합니다. 값을 명령행 인수나 로그에 넣지 않습니다.

- `CLOUDFLARE_ACCOUNT_ID`: Cloudflare 계정 ID
- `CLOUDFLARE_API_TOKEN`: 버킷과 공개 도메인 상태를 읽을 수 있는 최소 권한 토큰
- `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`: 해당 버킷에 세 고정 키를 읽고 쓸 수 있는 R2 S3 자격 증명

운영자가 Cloudflare 대시보드에서 계정 전체 R2 Standard 무료 저장 여유를 확인한 뒤에만 아래 두 플래그를 함께 씁니다. 이 작업에서는 실행하지 않았습니다.

```powershell
node updates/publish.mjs <위와-같은-검증-인수> `
  --publish `
  --confirm-account-free-headroom
```

게시 도구는 쓰기 전에 다음을 순서대로 확인합니다.

1. Cloudflare API에서 버킷 이름과 기본 저장 클래스 Standard를 확인합니다.
2. `r2.dev` managed domain이 꺼져 있고 custom domain이 전혀 없는지 확인합니다.
3. S3 `ListObjectsV2`가 잘리지 않았으며 기존 키가 고정 세 키의 부분집합이고 모두 Standard인지 확인합니다.
4. 기존·최종·업로드 중간 저장량이 APK 합계 384 MiB와 manifest 16 KiB를 넘지 않는지 확인합니다.
5. `current.apk`, `recovery.apk`를 이 순서로 올리고 각각 크기·Content-Type·Cache-Control·custom metadata를 `HeadObject`로 확인합니다.
6. 두 APK 확인이 끝난 뒤 `manifest.json`을 마지막으로 올리고 전체 inventory가 정확히 세 키인지 다시 확인합니다.

업로드는 R2의 S3 호환 `PutObject`를 사용하며 SHA-256 checksum을 요청에 포함합니다. AWS 재시도 횟수는 1로 고정합니다. 게시 중 실패하면 자동 삭제, 자동 환불, 무한 재시도 또는 유료 플랜 전환을 하지 않습니다. manifest를 마지막에 올리므로 중간 실패 시 기존 manifest가 유지되며, 원인을 확인하고 같은 dry-run부터 다시 시작해야 합니다.

기존 세 키를 교체하는 도중 APK 하나만 새 파일로 바뀌고 manifest 게시가 실패하면, 기존 manifest와 APK metadata가 달라져 해당 다운로드가 일시적으로 503으로 닫힐 수 있습니다. 이때 객체를 삭제하거나 manifest를 손으로 고치지 않습니다. 처음 검증한 `current.apk`, `recovery.apk`, `manifest.json` 세 파일이 그대로인지 다시 dry-run한 뒤 같은 `--publish --confirm-account-free-headroom` 명령을 한 번 다시 실행합니다. 고정 키를 같은 내용으로 덮어쓰고 manifest를 마지막에 재확정하는 절차가 복구 경로입니다. 게시 도구는 각 PUT과 이어지는 HEAD 중 하나라도 실패하면 뒤의 PUT을 실행하지 않습니다.

R2 S3 `PutObject`의 단일 객체 한도는 5 GiB이므로 약 125 MB APK를 custom metadata와 함께 한 번에 올릴 수 있습니다. Wrangler의 단일 객체 업로드도 315 MB까지지만 필요한 custom metadata 입력을 제공하지 않으므로 이 게시 경로에는 쓰지 않습니다.

- [R2 객체 크기 제한](https://developers.cloudflare.com/r2/platform/limits/)

## 요청 예산과 한계

인증이 성공한 요청만 고정 이름의 SQLite Durable Object에서 예약합니다. manifest 조회는 UTC 기준 일 100회·월 1,000회, APK 다운로드는 일 4회·월 20회, 다운로드 바이트는 월 4 GiB가 상한입니다. 다운로드는 manifest 조회 예약 뒤 R2 manifest를 읽고, 정확한 APK 크기를 다시 예약한 뒤 APK를 한 번 읽습니다. 승인된 예약만 SQLite row에 기록하며 거절·저장 오류·응답 유실은 R2 접근 없이 닫힙니다. 스트림 오류는 재시도하거나 예약을 되돌리지 않습니다.

이 예산은 Worker 안에서 인증된 요청의 R2 접근만 제한합니다. Worker Free의 계정 전체 일 100,000 요청은 Worker 코드에 도달하기 전에 소진될 수 있습니다. R2 무료 사용량도 계정 전체에서 다른 앱과 공유되므로 이 코드가 무료 범위를 보증할 수 없습니다. Cloudflare Budget Alerts는 알림만 보내며 사용량을 중지하거나 상한으로 막지 않습니다.

- [Workers 계정 요청 한도](https://developers.cloudflare.com/workers/platform/limits/)
- [R2 무료 사용량과 계정 단위 과금](https://developers.cloudflare.com/r2/pricing/)
- [Budget Alerts는 사용량을 중지하지 않음](https://developers.cloudflare.com/billing/manage/budget-alerts/)

## 아직 수행하지 않은 작업

R2 구독 활성화, 버킷·Durable Object 생성, secret 등록, Worker 배포, R2 업로드와 Pages 배포는 이 로컬 구현에서 수행하지 않았습니다. `updates/wrangler.jsonc`의 설정과 세 secret·자격 증명을 운영자가 검토한 뒤 별도 승인된 배포 단계에서 진행해야 합니다.
